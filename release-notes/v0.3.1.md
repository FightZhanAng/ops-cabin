# 运维舱 v0.3.1

以**修正判据与误报**为主的补丁版，来自对全仓的一次代码审查（47 条，逐条去向见仓库里的
[`CODE-REVIEW-REPORT.md`](https://github.com/FightZhanAng/ops-cabin/blob/main/CODE-REVIEW-REPORT.md)）。
没有新增功能，但有几处会直接影响你对界面读数的信任。

## 判据不会再误报

- **结束进程不再假报成功。** 非管理员会话下遇到受系统保护的进程（135、445 这类端口的
  属主基本是它们），原先界面会弹「已结束」，而进程还在、端口还占着。现在会如实说明
  「权限不足（该进程受系统保护或属于其他用户）」。
- **路径失效的判定更保守。** 只有**确证**文件不存在才算失效；长路径、读不到、解析不出
  的一律按「判不了」处理，不再当成失效。失效才会解锁不可逆的「删除登记」——这是本次
  审查里最危险的一环：以前一个含空格的长路径可能被截断成不存在的片段，于是把还在跑的
  自启项显示成「路径失效」。
- **服务状态读不到时会说「读不到」。** 以前采集失败与「你还没关注任何服务」都会得到空
  列表，面板会印出「N 个关注 · 全部在跑」——一次采集故障被显示成一切正常。现在会写明
  「状态读不到」，并附上原因（例如 PowerShell 不可用）。
- **计划任务不再把正常任务报成失败。** 补齐了调度器的官方成功状态码，并且不再把任务
  返回的自定义成功结果误判为失败（本机实测：一条 BitLocker 维护任务被长期显示成「失败」）。
- **「快捷方式指向的程序还在不在」判得准了。** 以前判的是「快捷方式自己在不在」，而那个
  文件必然存在，于是「程序已卸载、只剩一个空快捷方式」这种最典型的残留永远判不出来。

## 破坏性操作更收敛

- **白名单里的目录不会再被连父目录一起删掉。** 例如你把 `%TEMP%\keep` 设为保护目录，
  以前清理整个 `%TEMP%` 时会把它一起带走（而且「预计释放」还没算它）。这类候选现在会
  直接从清单里剔除。
- **用户名或临时目录含单引号的机器上，清理不再失败。** 顺带修掉一个更隐蔽的形态：含
  两个单引号时命令会「成功返回」，但读到的内容是错的。
- **清理失败一定有提示。** 以前准备删除清单时出错会穿透成未处理的 Promise 异常——你走完
  二次确认后对话框停在原地、按钮恢复可点、没有任何说明。

## 端口与服务

- **同号的 TCP 与 UDP 都会看。** 以前只跟踪其中一个协议（排序在前的 TCP），UDP 侧被占用
  或释放不产生任何提醒，显示的占用者也可能不是真正变化的那一个。
- **结束进程前会核对快照新鲜度。** 采集连续失败时旧快照可能已经放了很久，期间进程号可能
  被新进程复用——现在过期一律拒绝并提示刷新，避免误杀。
- **页面异常时不再留下常驻采集。** 渲染进程崩溃或重载后，端口采集不会继续以 2 秒节奏跑。
- **关注服务刚加进来时，基线建立不再被推迟最多一分钟。**

## 安全边界

- **导航与 IPC 都收紧到「只有本应用自己的页面」。** 以前放行的是整个 `file:` 协议——你
  下载目录里的任意 `.html` 打开都算合法页面，而它会拿到完整的应用能力（含永久删除、
  结束进程、UAC 提权、安装更新）。现在按入口文档精确比对，并且每个 IPC 通道都会校验发起方。
- **提权助手的请求文件与本次调用绑定**（校验文件名里的随机数与内容一致），并以独占方式创建。

## 其他

- 大文件扫描加了超时兜底，扫描进程卡死不会再让进度条永远转。
- 趋势图不会再因系统时间回拨而错乱。
- 同时弹出两条通知时，先弹的那条点了也有反应。
- 窗口位置改用更准确的时机记录。
- 新增 CI：push 与 PR 上自动跑类型检查与构建。

## 已知情况

- **渲染进程沙箱未开启。** 审查条目里建议打开，实测发现它会让渲染层的 `window.close()`
  变成**销毁窗口**（可取消的关闭事件不再发出），破坏「关窗只隐藏、托盘常驻」的既有行为，
  因此回退。实测结论已写进代码注释，要启用需作为一次独立决定。
- 测试套件 `e2e-scan` 存在**既有失败**（改动前同样失败，与本次无关），不在本版范围内。
