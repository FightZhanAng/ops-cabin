# M15 规格：启动项 / 计划任务可写化 + 磁盘扫描扩展

> 2026-10-13 · 状态：已对齐（拷问式对齐产出），待拆分任务
> 术语以根目录 `CONTEXT.md` 为准；提权取舍见 `docs/adr/0001-写操作提权.md`

## 1. 问题陈述

- **启动项页与计划任务页目前只读**：用户看到「路径失效的残留」「不该在跑的任务」，只能自己跳去任务管理器 / 任务计划程序处理。两页回答了「谁在跑」，却接不上「把它关掉」。
- **旧设计注释（`StartupPanel.tsx`）记录过押后条件**：「写要等先有备份与一键还原」。本批正面满足其精神而无需备份体系 —— 禁用/启用天然可逆（只翻启用位），删除登记只对零恢复价值的失效项开放（见 D2 / D7）。
- **磁盘页的大文件扫描入口单薄**：协议层与 worker 本已支持多根（≤8），UI 只放开单目录；其余盘符要整盘扫得自己选到盘根。清理位置清单也停在 14 个老位置，浏览器缓存 / 着色器缓存这类高价值、零风险的战场没有覆盖。

## 2. 方案概述

**A. 可写化（启动项 + 计划任务，两页同款）**

- 每行一个开关（禁用 / 启用，可逆）；失效项行附加「删除登记」（二次确认、不可逆、只动登记不碰程序本体）。
- 写入走统一执行器：渲染层只给 `id`，主进程从**自己刚采集的数据**重建操作参数（绝不信任渲染层传参）；免提权动作直接执行，需管理员的动作经按需提权由受控助手执行单条操作。
- 结果如实上报：成功 / 已取消（UAC）/ 被拒绝 / 条目已变化（stale）/ 失败原因，不静默重试。

**B. 磁盘扫描扩展**

- 大文件入口：分区列表每颗盘「扫这颗盘」+「选择目录…」多选（≤8 根）；多根结果合并按大小排序。
- 清理位置：加一轮低风险缓存（浏览器 / 着色器 / 编辑器；%LOCALAPPDATA% 系、免提权、自动重建）。

## 3. 接缝（深模块）

- **复用**：`startup:list` / `tasks:list`（采集与报告形态不变，只加写通道）；`startScan` 的 `largeFileRoots` 数组（≤8 根已就绪，无需新 IPC）。
- **新增一条写通道**：`auto:apply(op)`，`op = { target: 'startup' | 'task', action: 'toggle' | 'delete', id, enabled? }`。
- **新增执行器模块**（唯一写实现方）：参数重建（id → 六个已知键 / 启动文件夹 / 任务路径）+ 权限判定 + 直写或转助手；直写与助手两条路共用同一校验与同一执行代码。
- **助手入口**：`ops-cabin.exe --apply-op <payload 文件>`，在加载窗口与单实例锁之前的极早分支执行并退出；payload 与 `auto:apply` 共用同一 op schema。

## 4. 用户故事

**启动项（可写化）**

- S1 每个自启项行有开关；点按后该行状态翻转（「正常」↔「已禁用」）、计数更新，完成后强制重读并持久。
- S2 禁用只写启用位（StartupApproved 首字节 `0x03`；启用写回 `0x02`），条目其余字节（时间戳）原样保留；反复切换不损耗。
- S3 HKCU 项与用户启动文件夹项：全程无 UAC 弹窗。
- S4 HKLM 项与公共启动文件夹项：点按时弹一次 UAC（身份显示「运维舱」）；同意后完成；取消则行状态不变并提示「已取消（未提权）」。
- S5 「路径失效」与「已禁用 · 残留」的行显示「删除」；点按 → 二次确认（写明不可逆、只删登记不碰程序）→ 删除成功后行消失、计数更新。
- S6 非失效项没有「删除」入口；主进程同样拒绝（伪造的失效删除请求返回拒绝 —— 主进程按自采集数据复核）。
- S7 操作进行中该行控件禁用防连点；成功后立即强制重读该页。

**计划任务（可写化）**

- S8 任务行有开关；禁用后进入「已禁用」档、不再计入「需留意」（既有判据不变）；启用后恢复。
- S9 「删除」只对路径失效（missing）的任务开放，确认流与启动项相同。
- S10 schtasks 失败（权限不足、任务已被外部删除等）与 UAC 取消均如实提示；两页共享同一交互与提示口径。

**磁盘（扩展）**

- S11 分区列表每颗盘一个「扫这颗盘」入口 → 以盘根为根跑大文件扫描；跳过清单、白名单、受限条目计数照旧。
- S12 「选择目录…」可多选（≤8）；多根结果合并进大文件档按大小排序；进度条与取消照旧。
- S13 新清理位置逐条标风险档出现在「安全清理 / 开发缓存」；文件被占用时按既有「缩略图缓存」口径处理（标注而非失败）。
- S14 白名单、系统保护名单、默认删除进回收站等既有防线全部不变。

## 5. 已定决策

- **D1** 两页都做（启动项 + 计划任务）。
- **D2** 开关为主 + 失效项可删；删除只删登记；路径判不了的条目不算失效项。
- **D3** 提权 = 按需提权；受控助手 = 应用自身（`--apply-op`）；取消 / 失败如实上报，不静默降级。
- **D4** 助手只接受封闭操作集（六个已知注册表键下的值操作 + 计划任务启用/禁用/删除），永不接受任意路径或任意命令 —— 这是安全边界。
- **D5** 大文件入口 = 盘符快捷 + 多目录（≤8）；协议与 worker 已就绪，仅放开 UI。
- **D6** 清理位置加一轮低风险缓存；系统级大块（Windows 更新缓存 / Windows.old）明确不进批。
- **D7** 删除一律直接删除、不进回收站：对象是零恢复价值的失效项；统一语义，避免「注册表不可逆、.lnk 可回收」的不对称。
- **D8** 主进程不信任渲染层：op 只带 id，参数一律由主进程从自采集数据重建；条目对不上（stale）一律拒绝。

## 6. 测试决策

- **复用 e2e 框架**（真实开窗、驱动界面、断言 DOM 与 IPC）。可写化新增一套 `scripts/e2e-autostart.mjs`；磁盘扩展在既有 `e2e-scan.mjs` / `e2e-disk.mjs` 上扩展（收尾归属随拆分调整）。
- **免提权路径全端到端**：夹具在 HKCU Run 与用户启动文件夹创建带标记的条目（含指向不存在路径的失效项）→ 界面驱动开关 / 删除 → 断言注册表字节、文件系统、UI → 清理夹具。
- **提权路径**：UAC 无法自动化 —— 助手分支以非提权方式直接调用（走同一条代码）验证执行与结果上报；UAC 弹窗全链进人工清单，强度如实记录（沿项目惯例）。
- **任务侧**：用 schtasks 创建 / 清理带标记的测试任务，禁用 / 启用往返 + 删除；若本机权限模型不允许，退化并如实记录。
- **真值表**：启用位编码（保留时间戳字节）、op 校验（伪造 id / 非失效项删除 / stale）、封闭操作集白名单。
- **完成定义**：`pnpm typecheck` + `pnpm build` + 既有十套 e2e 全绿 + 新套全绿 + 冒烟六页 × 深浅截图更新。

## 7. 明确不做

- 不吃系统级大块：Windows 更新缓存、Windows.old、回收站清空。
- 不做「备份与一键还原」体系 —— 由 D2 / D7 的零价值删除边界替代；未来若开放任意项删除，须先补备份。
- 不做提权重启、不做常驻高权限。
- 不动服务页（启停不在本批）。
- 不发通知（写操作由用户发起，无信号可推）；侧栏徽标口径不变（失效数删除后自然回落）。

## 8. 补充说明

- **受控助手的威胁模型**：助手可被同用户级攻击者伪造调用，但最坏影响被限制在封闭操作集内（禁用/启用或删除本机自启登记与任务），换不来任意提权动作 —— 这是 D4 存在的理由。
- **UAC 身份**依赖打包物元数据（electron-builder productName「运维舱」）；dev 模式弹窗显示 Electron，记录在案。
- **文案更新点**：StartupPanel / TasksPanel 的「只读清单」提示句、DiskView 大文件档空态提示（补盘符入口）、README 功能表启动项行与磁盘行。
