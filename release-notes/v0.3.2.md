# 运维舱 v0.3.2

以**修好清理本身**为主的补丁版。上一版能让界面上的读数不再撒谎，这一版解决的是更下面的
问题：清理按钮按下去之后，到底删掉了什么。

## 清理不再被几个小文件连坐

- **一项里有文件被占用，其余内容照样会删掉。** 以前是把整个目录一次交给 Windows 的删除
  接口，而它对"部分失败"只回一个错误码；**回收站模式下遇到内含被占用文件的目录，它会直接
  放弃整项**——一个字节都不删。于是出现"3.5 GB 只因为 20 个小文件被占就一项都没删成，
  界面还告诉你『1 项失败（文件正被占用）』"。现在按候选逐条目执行：能删的当场删掉，
  删不掉的才单独报出来。
- **释放量按实际删掉的量算。** 以前只要有一项没删完，整项都记成失败、释放量记 0，
  连已经删掉的部分也一起"消失"了。现在会量出残留，`已删 = 扫描值 − 残留`，
  部分成功也如实计入。
- 占用是临时的：关掉占用它的程序再清一次就能清掉剩余部分。

## 告诉你到底是哪个进程占着

- **「文件正被占用」现在会点名。** 通过 Windows 的 Restart Manager（安装程序用来判断
  "这个文件能不能替换"的官方接口）查出持有句柄的进程，界面直接显示
  **程序名与进程号**（例如 `Microsoft Edge（PID 25188）`），并列出被占的具体文件名。
- 按原因给出下一步：被占用就说关哪个程序、回收站被整体取消就说清原因、权限不足就提示
  需要管理员。

## 清理结果看得见

- **没删干净时对话框不再直接关掉，而是切到结果面板**：逐项显示残留量与文件数、
  被占文件、持有进程，以及该项已删掉了多少。
- 失败项继续留在列表里，可以直接再清一次。

## 行为变更（请留意）

- **回收站模式遇到被占用文件时，未被占用的那部分是被"永久删除"的**，不进回收站。
  这是为了让"能删的先删掉"成立：Windows 的回收站接口在这种目录上会整体放弃，绕不过去。
  对话框里会明确写出这一句，不会让你以为它进了回收站。
- **被占用的文件绝不会被强行删除。** 不会为了"清干净"去结束进程、改权限或降级成永久删除。

## 内部

- 修掉一个会让清理**整体失效**的隐患：传给 PowerShell 的脚本编码后逼近 Windows 的
  命令行长上限（32767 字符），再加几行就会被系统拒掉、报一句很难看懂的
  `spawn ENAMETOOLONG`。现在超长脚本自动改走脚本文件。
- 新增端到端用例 `scripts/e2e-disk-locked.mjs`：用真实占用句柄覆盖"回收站整体取消、
  永久模式部分成功、界面上点名进程、释放句柄后重清"四条链路。
