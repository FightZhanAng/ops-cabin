# 启动项页（Startup）· v2 页面规范

> 覆盖 Master 的页面级规则；其余一切以 `MASTER.md` 为准。
>
> **这一页底下有两个 Tab**：`开机自启`（默认档）与 `计划任务`。两者同族 —— 都在回答
> 「谁在开机 / 按时自己跑」。**刻意不新开侧栏页**：侧栏项数是 e2e 的精确契约，
> 且这两份数据对用户来说是同一个问题的两面。

## 页面职责

回答三件事：**开机慢到底谁在拖**、**哪些自启其实早就没用了**、**除了自启还有谁在后台按时跑**。

- 「开机自启」：五个来源一次读全（注册表三处 + 启动文件夹两处），按来源分组陈列，并标出一条自启项是否还会真的生效。
- 「计划任务」：任务计划程序里**非微软自带**的任务（`\Microsoft\*` 整片跳过），这是「谁在定时联网」的答案 —— 遥测上报、自动更新、定时检查都在这里，而它们**全都不在** Run 键里。

## 零件用法

- 统计块四格（`startup-stats` / `tasks-stats`）：用抽出的共用零件 `StatGrid`
  （`grid gap-px bg-line` 拼合、每格 `bg-panel` —— 与 Plate 同一套发丝线语言，不是四张卡片）。
  失效数 / 需留意数 > 0 时该数字用 `text-warn`。
- 两个 Tab 各自的筛选用 `Rocker`（自启：全部 / 仅失效；任务：全部 / 仅需留意 / 已禁用），
  刷新按钮是 `outline xs`（禁用中显示「读取中…」）。
- 清单按分组（自启按来源、任务按文件夹），**分组顺序固定**（自启是 `SOURCE_ORDER` 五个来源；
  任务沿用采集器的排序：根目录最前 → 文件夹 → 名字）。空组不显示。**不按条数排** ——
  位置稳定才好找，按条数排会让分组在装一个软件后就换位置。
- 行：`Lamp` + 名称 + 副行（自启是命令行、任务是可执行动作）+ 右侧状态词。**「正常」不亮灯**（灯只标异常），其余档亮灯。
- 两个 Tab **按需挂载**：计划任务那份要起一次 COM 枚举（本机 1.5 秒），没切过去就不采。

## 两处容易做错的判定（改动前必读）

- **`StartupApproved` 的启用位必须读。** 任务管理器把「已禁用」记在 `HKCU/HKLM\...\Explorer\StartupApproved\{Run,Run32,StartupFolder}`，值首字节 `0x03` = 禁用，`0x02/0x06` = 启用。不读它，就会把已经禁掉的自启项继续当成「每次开机都在跑」，用户会去清一个根本没在跑的东西。字段缺省 = 启用。
- **`invalid` 只算「启用中」的项，行状态必须与它同义。** 已禁用的项路径丢了也无害，算进「路径失效」会让数字虚高，用户照着清完发现没变化。**同理行的灯也不能把「已禁用且路径没了」点亮成「路径失效」** —— 否则统计块说 0、点进「仅失效」却有 1 行，两个都在讲同一件事却说不到一起。这一档单独记作 `stale`，两个事实都留住。**这两个判定改任一边，另一边都要一起改。**
- 裸命令名（无盘符、无路径分隔符）按**有效**处理：走 PATH 解析，判成失效会制造假警报。

## 计划任务档：三处容易做错的判定（改动前必读）

- **`LastTaskResult` 不能按 `!= 0` 判失败。** 调度器把自己的状态也记在这同一个字段上：
  `0x41300` 就绪 / `0x41301` 正在运行 / `0x41302` 已禁用 / `0x41303` 尚未运行 /
  `0x41304` 没有更多运行。本机 17 个任务里有 6 个是这两个值 —— 判错就让假警报占多数。
  入参一律 `>>> 0` 归一化（PowerShell 的 `[long]` 可能给出负数）。
- **`0x8007xxxx` 的低 16 位才是 Win32 错码，掩码必须 `>>> 0`。**
  JS 的 `&` 走有符号 32 位：`0x80070002 & 0xffff0000` 得到 `-2147024896`，与字面量
  `0x80070000`（`2147942400`）永不相等 —— 少了 `>>> 0`，整张 Win32 文案表就是死代码
  （这个 bug 真发生过，靠自检抓出来的）。
- **「已禁用」不是异常，而且必须先短路。** 禁用的任务根本不会运行，路径没了、上次结果难看
  都不该算成问题 —— 把禁用的项并进「失败」会让用户去修一个本来就没在跑的东西。
  `resolveState()` 的顺序（disabled → missing → failing）与 `report.attention` 的口径绑死，改一边就要改另一边。
- **任务 XML 的 `<Command>` 可能自带引号**（本机 WPS、Snipaste 都如此）→ 必须走
  `parseExecPath`，直接 `existsSync('"D:\...exe"')` 会 100% 误报「路径失效」。
- **`NextRunTime` 只在「真的会有下次」时才印。** 登录 / 开机触发的任务没有排期（印成
  「下次 —」读起来像出错）；已禁用的任务可能留着一个陈旧值（印出来等于告诉用户「今晚会动」）。
  两种情况都省略，完整信息留在 `title` 里。
- **没有触发器的任务不是异常**：它只在被手动或其他任务调用时跑（本机 Snipaste）。按「手动」呈现。
- 取数走 **COM `Schedule.Service`** 而不是 `Get-ScheduledTask`：cmdlet 逐任务走 WMI 往返
  （本机 180 个任务 = 3.7 秒），COM 一次枚举只要 1.5 秒。代价是枚举值是裸整数，
  触发类型映射表在**本机全部 180 个任务**上与 cmdlet 的 CIM 类名逐条对齐过，不是照文档抄的。

## e2e 契约（不许动）

- 元素：`startup-view`（`data-tab`）、`tab-startup`、`tab-tasks`、
  `startup-stats`（`data-total` / `data-invalid` / `data-disabled`）、`startup-group`（`data-source`）、
  `startup-row`（`data-state` / `data-name`）、`startup-filter-all`、`startup-filter-invalid`、`startup-refresh`、
  `tasks-stats`（`data-total` / `data-attention` / `data-disabled` / `data-scanned` / `data-skipped`）、
  `tasks-group`（`data-folder`）、`task-row`（`data-state` / `data-name` / `data-running` / `data-triggers`）、
  `tasks-filter-all`、`tasks-filter-attention`、`tasks-filter-disabled`、`tasks-refresh`。
- 结构：`startup-row` 数 === `data-total`（全部档下每一项都渲染）；`data-invalid` === 行内 `data-state="invalid"` 的条数；`data-disabled` === `disabled` + `stale` 的条数；「仅失效」档的行数 === `data-invalid` 且每行都是 `invalid`；`data-source` 是固定顺序的子序列。
- 任务侧：`task-row` 数 === `data-total`；`data-attention` === `failing` + `missing` 的条数；`data-disabled` === `disabled` 的条数；「仅需留意」/「已禁用」档的行数分别等于对应读数；`data-scanned ≥ rows + data-skipped`；`data-folder` 不出现 `\Microsoft` 前缀；四档状态互斥完备（四者之和 === `data-total`）；已禁用的行**不出现**「下次」字样；任何行**不出现**「下次 —」。
- 就绪轮询必须**显式判元素存在**再判文案：`!document.querySelector(S)?.textContent.includes('读取中')`
  在元素未挂载时给 `undefined`，取反即「已就绪」，会把「还没渲染」当成「读完了」（真踩过）。
- 服务/自启/任务的读写都走主进程缓存（`STARTUP_TTL` 30s / `SERVICES_TTL` 15s / `TASKS_TTL` 60s + 并发合流），侧栏与页面同时挂载只起一次 PowerShell / COM 枚举。
