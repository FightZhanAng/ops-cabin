# 写操作提权：按需提权 + 应用自身助手

M15 要给启动项与计划任务加写操作，而写入落在不同权限域：HKCU 与用户启动文件夹免提权，HKLM、公共启动文件夹与多数计划任务需要管理员。我们决定**动作时按需弹一次 UAC**，由应用自身以助手模式（`ops-cabin.exe --apply-op <临时文件>`）执行单条操作：主进程从自己采集的数据重建操作参数写入临时文件，助手在加载窗口与单实例锁之前的极早分支执行并退出。免提权动作永不弹窗；UAC 弹窗的应用身份是「运维舱」而不是 PowerShell。

## 备选方案（被否决）

- **提权重启**：启动时选一次「以管理员身份重启」，本次会话内写操作全畅通。否决：重启交接成本高（单实例锁交接、托盘重建），且若用户倾向常态提权，等于把摩擦前置到每次启动。
- **免提权裁剪**：只做免提权部分，HKLM 类只提示不代做。否决：覆盖不全 —— 不少安装程序把自启写在 HKLM，而这正是最想关的那批。

## 后果

需要长期维护一条受严格校验的 CLI 助手入口：助手只接受封闭操作集（六个已知注册表键下的值操作 + 计划任务的启用/禁用/删除），永不接受任意路径或任意命令 —— 即使被同用户级攻击者伪造调用，最坏影响也被限制在这个集合内。
